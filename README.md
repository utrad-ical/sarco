# サルコペニア解析ツール

[English](README.en.md)

このリポジトリは、体幹部CT画像からサルコペニア解析を行うためのツールです。[CIRCUS](https://circus-project.net/) のCADプラグインとして使用されることを想定しています。

## 機能

*   **自動的な筋肉領域のセグメンテーション:** U-Netベースの深層学習モデルを利用して、CT画像から骨格筋領域を自動的にセグメンテーションします。
*   **定量的な解析:** サルコペニアに関連する以下の指標を計算します。
    *   骨格筋面積 (SMA)
    *   平均骨格筋密度 (MSMD)
    *   内臓脂肪面積 (VAT)
    *   皮下脂肪面積 (SAT)
*   **推定:** 年齢、造影相、身長・体重を推定し、CT値の指標を単純CT（時相0）相当に換算します（[ct25d-regressor](https://github.com/hanaokalog/ct25d-regressor) を使用）。
*   **入力の向きの自動補正:** 頭尾方向が逆に並んだ入力（足側が先頭）を自動で判定し、正しい向きで解析します。
*   **CIRCUSとの連携:** CIRCUSのCADプラグインとして動作し、解析結果を分かりやすく表示します。

## 動作の仕組み

`processsingle.sh` は次の順に処理します。

1.  **向きの判定:** `orientation.py check` が入力の頭尾方向を判定し、足側が先頭ならスライスを並べ替えた作業用コピーを作ります（以降はすべてこのコピーで処理）。
2.  **L1/L3 の位置推定:** `lumbar.py` が投影像から高さを推定し、`lumbarmodifier.py --mode passthrough` が撮影範囲の端の判定をして `l1mod.txt`/`l3mod.txt` に書きます（下の「L1/L3 の位置推定と撮影範囲」）。
3.  **セグメンテーション:** `sarcosegmentation.py` が、事前学習済みのU-Netモデルで L1/L3 断面の筋肉・椎体を領域分割します。
4.  **計算:** `sarcocalculate.py` が、領域分割の結果とCT画像からサルコペニア関連指標と内臓領域マスクを求めます。
5.  **推定:** `estimate.py` が年齢・造影相・身長体重と時相0相当値を求めます。
6.  **向きを戻す:** `orientation.py restore` が、結果ラベルとスライス番号を入力の元の並びに戻します。
7.  **まとめ:** `resultuniter_circus.py` が結果の表を `results.json` にまとめます。

計算された指標や生成された画像などの結果は、CIRCUSのインターフェース上に表示されます。

## 使い方

このツールは、CIRCUSプラグインとして実行されることを意図しています。このリポジトリの `Dockerfile` を用いて、必要な依存関係と解析スクリプトを含むDockerイメージをビルドすることができます。

CIRCUSのインターフェースからプラグインを起動すると、`processsingle.sh` スクリプトが実行され、単一のケースに対して解析が行われます。

## スクリプト

*   `bin/orientation.py`: 入力の頭尾方向の判定（`check`）、結果の並びの復元（`restore`）、判定器の学習（`train`）。
*   `bin/lumbar.py`, `bin/lumbarmodifier.py`: L1/L3 の高さの推定（`lumbarmodifier.py` の分類器は推論では使っていません）。
*   `bin/sarcosegmentation.py`: U-Netモデルを用いて筋肉のセグメンテーションを実行します。
*   `bin/sarcocalculate.py`: セグメンテーション結果からサルコペニア指標を計算します。
*   `bin/estimate.py`: 年齢・造影相・身長体重・時相0相当値の推定。
*   `bin/resultuniter_circus.py`: 結果の表を `results.json` にまとめます。
*   `bin/tools/make_visceral_masks.py`: 既存の結果から内臓領域マスクを作り直します。
*   `processsingle.sh`: 単一ケースの解析プロセスを統括するメインスクリプトです。
*   `Dockerfile`: プラグインのDockerイメージをビルドするために使用します。
*   `plugin.json`: CIRCUSプラグインの設定と表示方法を定義します。

## 学習データの扱い

学習時（`--mode train`）は、`--labelused` のラベルが1画素もない症例を自動で除外し、除外した症例のラベルファイルを表示します（`readfiles.drop_empty_labels`）。空のラベルのまま学習すると、lumbarmodifier と sarcosegmentation は0番スライスを正解として空のラベルで学習してしまうためです。推論時は除外しません。

## 内臓領域マスク

`sarcosegmentation.py` は、結果ラベル `<名前>_<L1|L3>.result.nii.gz` と並べて内臓領域マスク `<名前>_<L1|L3>.visceral.nii.gz` を出力し、`__result_<L1|L3>.csv` の `{<L1|L3>_visceral_path}` 列にそのファイル名を記録します（`sarcocalculate.visceral_mask`）。

*   マスクは、筋肉（ラベル1）に囲まれた領域（`get_visceral_region`）から、筋肉と椎体（ラベル2、3）を除いたものです。筋肉が最も多いスライス1枚だけに値1が入ります。椎弓・脊柱管は椎体ラベルに含まれないので、マスクに残ります。
*   画像の幾何情報（原点・画素間隔・向き）は元の体積と同じです。`tricolor<i>.nii.gz` にも幾何情報を付けるようにしました。
*   既存の結果から作り直すには `bin/tools/make_visceral_masks.py` を使います。GPUも再セグメンテーションも不要です。列 `gray`, `label`, `name` を持つCSVを渡すと、マスク、確認用PNG（CT・筋肉の輪郭が赤・椎体が青・内臓領域が緑）、各症例の確認用の数値を書いた `manifest.csv` を出力します。`muscle_coverage`（筋肉の中心から見て筋肉がある方向の割合）が低い症例は、筋肉の輪が途切れているので確認してください。

## 年齢・造影相・身長体重の推定と、時相0（単純CT）相当値

`processsingle.sh` は、L1/L3 の解析のあとに `bin/estimate.py` を実行します。結果は `__estimates.csv` に書かれ、`results.json` の `results.estimates` に入ります。推定には [ct25d-regressor](https://github.com/hanaokalog/ct25d-regressor) を使います（Dockerfile でコミットを固定してインストール）。`model/` にないチェックポイントの推定は飛ばし、残りはそのまま実行します。

*   **年齢** (`age`): L1/L3 の椎体髄質（ラベル3）と筋肉（ラベル1）の4モデル（`model/age_{marrow,muscle}_L{1,3}.pt`）を、逆分散で重み付けして統合します。統合後の幅は `model/age_combination.json` の係数で補正しています（4モデルは独立ではないため）。4モデルそれぞれの値と95%区間も `age_marrow_L1`, `age_marrow_L3`, `age_muscle_L1`, `age_muscle_L3`（`_sigma`, `_lo95`, `_hi95` 付き）として出力し、CIRCUS 上にも表示します。
*   **造影相** (`phase`, `phase_name`): 内臓領域マスクから L1/L3 で推定し（`model/phase_L{1,3}.pt`）、得られたレベルの確率を平均して最も確率の高い相を1つ選びます。v8.4.0 からは6相: 0 単純、1 早期動脈相、2 後期動脈相、3 門脈相、4 静脈相、5 平衡相（v8.3 までは5相で、3 門脈相、4 平衡相）。相の名前はモデルのクラス数で決まります（`estimate.PHASE_SCHEMES`）。`phase_correction.json` の `phases` の数がモデルのクラス数と違うときは、時相0相当値を出しません。**L1 か L3 の一方しか撮影範囲に入っていない場合**（上腹部のダイナミックCTなど）は、写っている方だけで推定します（`phase_n_levels` が 1）。両方とも範囲外なら推定しません。
*   **身長・体重** (`height`, `weight`): 体幹（腕と寝台を除いたもの）の投影像と L1/L3 断面から推定します（`model/bodysize.pt`, `ct25d.bodysize`）。一方のレベルしか撮影範囲にない場合は、そのレベルだけから推定します（`body_n_levels` が 1。学習時に一方を落とした例も混ぜています）。
*   **時相0相当値** (`<L1|L3>_<項目>_phase0`): MSMD, meanVAT, meanSAT, cortical_density, medullary_density, SASHI を、推定した造影相の線形式 `値0 = a + b × 値k` で単純CT相当に換算します（`model/phase_correction.json`、レベル・項目・相ごと。相0はそのまま）。式は同一検査の相0と相kの組から最小二乗で求めました（相1〜3 と 5: Dataset L、相1・2・4: Dataset O、相4・5: Dataset P）。SASHI は割合なので 0 も値として扱い、換算後は 0〜1 に収めます（v8.4.0 から）。

学習と評価（2026-10-02, 保留したテスト分割）:

| 推定 | テスト成績 |
|---|---|
| 年齢 骨髄 L1 / L3 | MAE 7.2 / 7.7 歳 |
| 年齢 筋肉 L1 / L3 | MAE 7.9 / 7.5 歳 |
| 年齢 統合 | MAE 6.9 歳 (Dataset L), 6.2 歳 (Dataset main)、95%区間の被覆率 0.98 / 0.97 |
| 造影相（6相、v8.4.0） L1 / L3 / 平均 | 正解率 0.85 / 0.81 / 0.88（全データセット、409系列）。Dataset L のみ平均 0.93（同じ系列で v8.3 の5相モデルは 0.92）。静脈相の再現率は 0.31 と低く、多くは門脈相か平衡相と推定されます |
| 身長 / 体重 | MAE 3.5 cm / 2.7 kg（Dataset main）。L1 だけ 4.2 cm / 3.4 kg、L3 だけ 4.2 cm / 3.2 kg |

学習データは Dataset L（1675系列、321人、造影相つき）と Dataset main（2039人、人が確認したラベル、身長体重つき）です。造影相（v8.4.0）には、Dataset P（胆膵のダイナミックCT。単純・静脈相・平衡相）、Dataset HC（全身の単純CT、学習は100人まで）、Dataset O（系列名から相を決めたもの）も加えました（データセットは下の「学習データ」）。分割は患者単位で train/val/test = 70/15/15（乱数の種 0）。L3 が L1 より頭側にある系列（L1/L3 ラベルの入れ替わり・複数撮影をつないだ体積など16系列）は学習から外しています。

## L1/L3 の位置推定と撮影範囲

上腹部だけのダイナミックCTのように、L1 か L3 が撮影範囲に入っていない検査があります。

*   `lumbar.py` のモデルは、撮影範囲を頭尾方向にランダムに切った画像で学習しています（`--online`。範囲は 120 mm〜全体）。尤度のピークが `model/l<1|3>_lumbar.ckpt.json` のしきい値より低ければ、そのレベルは範囲外（z = -1）とします。
*   `lumbarmodifier.py --mode passthrough` は `lumbar.py` の z をそのまま使い、最初か最後のスライスから 10 mm（`--edge_mm`）以内なら範囲外とします。レベルが範囲のすぐ外にあると、隣の椎体が端の近くに見つかるためです。
*   以前の `lumbarmodifier.py` の分類器（DenseNet による精密化）は使っていません。テスト分割では、正しい z を1スライスずらすことが 11〜17% あり、精度を下げていました。学習（`--mode train`）と `--mode test` は残してあります。

テスト分割（約300系列、5 mm 厚）を切り出した画像で、パイプライン全体（`lumbar.py` → `lumbarmodifier.py`）を評価した結果:

| | L1 | L3 |
|---|---|---|
| 範囲内: 見つかる | 0.99〜1.00 | 1.00 |
| 範囲内: スライスが一致 / ±1 以内 | 0.96〜0.97 / 0.97〜0.98 | 0.98〜1.00 / 0.99〜1.00 |
| 範囲外（端から 5〜30 mm 外）: 誤って見つける | 0.06 | 0.06 |
| 範囲外（30〜100 mm 外）: 誤って見つける | 0.00 | 0.00 |

以前のモデル（v8.2 まで）は、範囲外でも必ずどこかにレベルを見つけ、L3 が範囲外の画像の 24〜46% で別の椎体を L3 としていました。また範囲内でもスライスの一致は L1 0.89、L3 0.83 でした。

v8.5.0 の `lumbar.py` のモデルは、上の学習データに、全身の単純CT（Dataset HC）で sarco の結果を目で確認して正しかった系列（学習 L1 297 / L3 318 系列、足側先頭の体積は `{flip}` で頭側先頭にして読む）を加え、v8.4 のモデルから続けて学習したものです。上の表のテスト分割では v8.4 とほぼ同じ成績です（全体を入力したとき L1 が見つかる 0.997 → 1.000）。学習に使っていない 2544 系列（Dataset L、P、O、HC のテスト分割）で v8.4 と比べると:

| | L1 | L3 |
|---|---|---|
| 見つけた系列（v8.4 → v8.5） | 2282 → 2327 | 2123 → 2197 |
| 両方が見つけた系列で、選んだスライスの差が 5 mm 以内 | 2269 / 2281 | 2107 / 2121 |
| 食い違い（一方だけが見つけた、5 mm を超えてずれた）を目で確認: 正しかった数 v8.4 / v8.5 | 6 / 48（59 件中） | 5 / 82（92 件中） |

v8.5 だけが見つけた系列（L1 46、L3 76）の 9 割（L1 41、L3 72）は正しい位置でした。範囲外を誤って見つけたものなど、v8.5 の新しい誤りは L1 5、L3 4 です。また、Dataset HC で v8.4 が範囲外としていた系列（学習に使っていないもの）では、L1 32 系列中 24、L3 8 系列中 4 が正しく見つかるようになりました。

## 入力画像の向き

パイプライン全体（`lumbar.py` 以降）は配列の並び順で処理し、スライス0が頭側であることを前提にしています。ヘッダの z 方向は信用できない（Dataset L はすべて逆向き）ので、向きは画像から判定します（`bin/orientation.py`）。

*   判定器: 冠状断・矢状断の平均値投影と最大値投影（5 mm × 4 mm 格子、配列の並び順のまま）を入力とする小さなCNNです（`model/orientation.pt`）。学習データは Dataset L・Dataset main の全系列に、全身の撮影（Dataset HC）と Dataset P を加えたもので（v8.3.1 から。v8.3.0 までの判定器は全身の撮影の多くで向きを誤りました）、ランダムに上下を反転し、頭尾方向を 100〜640 mm に切り出し、切り出した範囲を入力窓のランダムな位置に置き（残りは空）、半数では撮影視野を狭めて学習しました（短い上腹部の撮影でも判定できるように）。テスト分割での誤り（しきい値 0.7、全長）: 正しい向きの入力の反転 0、足側先頭の見逃し Dataset L 0 / main 0 / P 0 / HC 1/71。
*   足側が先頭である確率が 0.7 を超えたときだけ反転します（`--threshold`。正しい向きの入力を反転する誤りの方が重いため）。
*   反転した場合も、出力する結果ラベル（`*.result.nii.gz`, `*.visceral.nii.gz`）と表のスライス番号は入力の元の並びに戻します。判定結果は `__orientation.json` と `results.estimates` の `input_feet_first`, `input_feet_first_prob` に残ります。
*   判定器がない場合（`model/orientation.pt` なし）は入力をそのまま使います。
*   身長体重の推定は物理座標で行うので、向きをそろえた後の配列の並びから座標系を決めています（ヘッダの z 方向は使いません）。

テスト分割（567系列を上下そのままと反転の両方で、撮影範囲を切り出して評価）での誤り率:

| 撮影範囲 | 正しい向きを反転してしまう | 逆向きを見逃す |
|---|---|---|
| 150 mm | 1.4% | 0.9% |
| 200 mm | 0.2% | 0.5% |
| 300 mm | 0.2% | 0.4% |
| 全範囲 | 0% | 0% |

（閾値 0.7。全3698系列の全範囲で誤ったのは、複数の撮影をつないだ体積など向きの定まらないものが大半でした。）

## テスト

```bash
pip install pytest   # ct25d-regressor, torch, SimpleITK, pandas, scipy も必要
python -m pytest
```

合成ファントム（筋肉の輪・椎体のある体幹）と、学習していない小さな ct25d チェックポイントを使うので、実データ・学習済みモデル・GPU は不要です。確かめていること:

*   `sarcocalculate`: SMA・MSMD・VAT・骨の値がファントムの既知の面積・CT値に一致する、空の結果では0。
*   内臓領域マスク: 筋肉と椎体を除いた輪の内側、筋肉が最も多いスライス、幾何情報の保持、`make_visceral_masks.py` の出力と manifest の追記。
*   向き: 特徴量がヘッダではなく配列の並びに従う、足側が先頭の入力の反転と結果の復元（ラベル・スライス番号・パス）、閾値未満では反転しない、判定器がなければそのまま、学習の実行。
*   `estimate.py`: 年齢の統合式（幅の補正を含む）、造影相が確率平均の最大、L1 だけ・L3 だけ・どちらもない場合、時相0相当値の式、チェックポイントが欠けた推定だけ飛ばす。
*   `resultuniter_circus.py`: `plugin.json` が表示するすべての値が `results.json` から引ける、推定がない・空の場合もまとめられる。

L1/L3 の位置推定とセグメンテーション（学習済みモデルが必要）は、Docker イメージで実際の症例を流して確認しています。

## 前処理のキャッシュ

体積の読み込み、リサンプル、腕の除去は時間がかかり、しかも同じ処理が何度も繰り返されます（L1とL3で同じ体積を処理する、学習のたびに同じ症例を前処理する、など）。そこで `lumbar.py`、`lumbarmodifier.py`、`sarcosegmentation.py` は、`--cache_dir` を指定すると症例ごとの前処理結果を保存し、次回以降はそれを使います（`bin/prepcache.py`）。

*   キャッシュの対象: lumbar の投影像（体積全体ぶん。データ拡張のずらしは行の切り出しで再現）、modifier の探索範囲、segmentation の対象スライス、計算段の体幹マスク。
*   キャッシュのキーは、入力ファイルのパス・サイズ・更新日時（`.mhd` はデータファイルも含む）と前処理の設定です。どれかが変われば作り直すので、古い結果が使われることはありません（古いファイルは残るだけです）。
*   結果はキャッシュなしの場合とビット単位で同じです。
*   シェルスクリプトは、推論では `$TEMPDIR/cache`、学習では `./train_temp/cache` を使います。環境変数 `SARCO_CACHE_DIR` で場所を変えられます。Docker では `/temp` は実行ごとに消えるので、実行をまたいで再利用したい場合は永続ボリュームを指定してください。
*   前処理のコードを変更して出力が変わる場合は、`bin/prepcache.py` の `CACHE_VERSIONS` の該当する番号を上げてください。

## Dockerイメージのビルド

Dockerイメージをビルドするには、リポジトリのルートディレクトリで以下のコマンドを実行します。

```bash
docker build -t sarcopenia-plugin .
```

推定用の ct25d-regressor は `Dockerfile` の `CT25D_COMMIT` で固定したコミットをインストールします（`--no-deps`、イメージの torch をそのまま使う）。ct25d を更新したら、この値も更新してください。

## 学習データ

すべて東京大学医学部附属病院の CT で、倫理審査委員会の承認を得て使用しています（単施設）。

| 名前 | 内容 |
|---|---|

## 想定する使い方と限界

*   **研究用です。** 診断や治療の判断に使う医療機器ではありません（承認を受けていません）。結果は人が確認してから使ってください。
*   対象は、腹部を含む成人の体幹部CTです。小児は学習データに含まれません。
*   単施設のデータで学習しています。ほかの施設・装置・撮影条件では成績が変わることがあります。
*   L1 か L3 が撮影範囲の端に近い場合や、移行椎など椎体の数に変異がある場合は、レベルを誤ることがあります。
*   造影相は静脈相の推定が弱く、多くは門脈相か平衡相と推定されます。
*   年齢の推定値は平均へ回帰します（若い人は高めに、高齢の人は低めに出ます）。
